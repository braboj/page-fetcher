## Current bottleneck

**Correctness (C-)** — two detection predicates fire on ordinary content,
and both failure modes are silent and terminal. A real 16.9 KB product page
containing the phrase "no longer available" is classified as a 404 and
returned as `ok=False` with no escalation and no cache write; a real article
containing "rate limit" is classified as a bot wall and fails every tier.
Neither raises, neither logs anything a caller can distinguish from a
genuine miss. For a fetcher whose entire value proposition is "picks the
tier for you", silently refusing fetchable pages is the worst available
failure mode.

## Correctness — Grade: C-

Role: reviewer hunting for paths that produce wrong results.

All nine findings below were reproduced. Reproduction snippets are in the
notes column.

| #   | Severity | Location                                    | Finding                                                                                                                                                                                                  |
| --- | -------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | CRITICAL | `detection.py:66-68` `ERROR_PAGE_PATTERNS`  | `no longer available` and `has been discontinued` are unanchored substrings matched over the first 20 KB of de-tagged text. A 16.9 KB product page whose body says "the silver finish is no longer available" returns `is_error_page → True`. In `_fetch_urllib` that is `_ERROR_PAGE`: terminal, no escalation, no cache, `ok=False`. |
| C2  | CRITICAL | `detection.py:35` `Rate.?limit`             | Matches the ordinary phrase "rate limit". An article about API rate limiting returns `is_bot_blocked → True`, so every tier's `looks_like_real_content` gate also rejects it. The page is unfetchable by any tier. |
| C3  | CRITICAL | `__main__.py:131-179`                       | The CLI exits **0** when every tier fails. Verified against an unresolvable host: empty stdout, exit code 0. Any script using `py -m pagefetch url && process` treats total failure as success.            |
| C4  | HIGH     | `network.py:747-761`, `763-801`             | In batch mode with a persistent Nodriver session, `_fetch_one_in_batch` never reads the cache — `opts.use_cache` is ignored on that path, so a fully cached batch refetches every URL through a headed browser. |
| C5  | HIGH     | `network.py:589-590`, `780-781`             | `--no-cache` / `use_cache=False` suppresses the cache *read* but not the *write*. Verified: a fetch with `use_cache=False` leaves `2dce0a4c50441bfc.txt` in the cache dir.                                 |
| C6  | HIGH     | `__main__.py:79-80`                         | Unknown flags are silently discarded (`if arg.startswith("--"): continue`). `--dyr-run` on a `--clean-cache` run does not dry-run — it **deletes**. A typo in the one flag that exists to prevent deletion causes deletion. |
| C7  | MEDIUM   | `network.py:103-122` `_decompress`          | A declared but unsupported `Content-Encoding` (e.g. `br`, `zstd`) falls through the `if` chain and returns the compressed bytes unchanged. Verified. They then decode to mojibake, which exceeds `MIN_REAL_CONTENT_BYTES` and is cached as a page — precisely the failure the function's own docstring says it exists to prevent. |
| C8  | MEDIUM   | `network.py:153-166` `_BatchSession.close()` | Teardown is three unguarded statements. Verified: when `nd_browser.stop()` raises, `loop.close()` never runs and the event loop's selector and file descriptors leak — the exact leak the docstring says the method prevents. |
| C9  | MEDIUM   | `chrome.py:29-30`, `network.py:193-195`     | `ChromeReaper.__init__` calls `atexit.register` with no unregister, and `NetworkFetcher` builds one per instance. Verified: 100 `NetworkFetcher()` constructions grow the atexit table from 1 to 101 callbacks, each of which shells out to `tasklist` at interpreter exit. |
| C10 | LOW      | `__main__.py:150`                           | `int(_flag_value(argv, "--wait") or 500)` is outside the `try`. `--wait abc` produces a raw `ValueError` traceback rather than the "Error: …" message every other bad input gets. Negative values are unvalidated. |
| C11 | LOW      | `network.py:780-781`                        | Batch writes the cache twice per URL — once inside `_fetch_single`, once in `_run_batch`. Verified: 2 `cache.write` calls per URL, and 1 write even on a pure cache hit (rewriting a file with its own contents). |

**Summary.** The escalation logic itself is sound and well tested; the
defects cluster at the edges — the pattern lists, the CLI boundary, and the
cache/batch interaction. C1 and C2 are the ones that matter: both are
one-line pattern problems with large blast radius, both silently return "no
content" for content that exists, and both are the kind of thing that shows
up as an unexplained gap in a scraped dataset months later. C3 and C6
compound it by making the CLI unable to signal failure and able to delete on
a typo.

## Recommended remediation order

Ordered by blast radius, not by effort.

1. **C1, C2** — anchor `ERROR_PAGE_PATTERNS` and `Rate.?limit` to page
   position or title context rather than free text; add a fixture test for
   a real page containing each phrase in body copy. Both are silent,
   terminal, and cause missing data.
2. **C3** — exit non-zero when no content was fetched (single and batch).
   Any pipeline built on the CLI is currently blind to failure.
3. **C6** — reject unknown `--flags` instead of discarding them. A typo in
   `--dry-run` currently deletes cache entries.
4. **Doc finding 9** — add a ruff `extend-exclude` for
   `docs/solid-ai-templates/` so the documented local gate passes again.
5. **C4, C5** — make `use_cache` mean the same thing on every path; decide
   and document whether `--no-cache` means "do not read" or "do not touch".
6. **C7, C8, C9** — unsupported encoding should fail the tier; guard each
   teardown step independently; make the reaper a shared default instead of
   per-instance.
7. **Tests finding 3, 4** — add `windows-latest` to the test matrix; cover
   `main()` argument parsing.
8. **Docs findings 3-6, 8** — add `CLAUDE.md` and `docs/dev-journal.md`
   first (both MUST), correct the test count, then ONBOARDING and PLAYBOOK.
